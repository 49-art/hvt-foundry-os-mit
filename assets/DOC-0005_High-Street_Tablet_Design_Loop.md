# DOC-0005 — High-Street Tablet Design Loop

Purpose A practical, repeatable path so any high-street business can be designed (or re-designed) live on a tablet with the owner, and any feedback or wishes can be brought back into the Foundry without friction or loss of constitutional discipline.

## The Loop (never needs to be perfect)

1. Open Session Create a Customer Session (SES-####) linked to the Business Type or Project.
2. Classify / Re-classify Use the existing Business Ontology (HVT-0006). Let the owner correct anything. The customer is always right.
3. Run Configurator ENG-0004 returns the current best match of Engines + Solution Components filtered by size, budget, and technical ability.
4. Owner Reviews on Tablet Show the proposed package in plain language. Owner can approve, reject, or state wishes.
5. Capture Wishes Every request becomes a Customer Wish (WSH-####). Use the owner’s own words.
6. Close Session Session status → Closed. All wishes are now permanent records.
7. Return Path (this is the key innovation) When you leave the tablet:
    - Open wishes automatically appear in the next Architecture / Engineering review.
    - Each wish is evaluated under Article XIV (Model-First) and Article II (Engine Search).
    - Result is either:
    - a. Re-configuration using existing engines, or b. Formal Engine Search logged, or c. Explicit decision that the wish is out of scope for now (still logged).
8. New configuration offered back to the customer The owner sees the updated proposal and can approve again. Cycle repeats as many times as needed.

## Explicit Rules

- The system is allowed to be incomplete.
- The customer’s stated reality overrides any prior classification.
- No wish is ever deleted — only superseded.
- Customer assets remain customer assets (Article VIII).
- Speed of iteration is more important than completeness of the ontology.

## First Target

Hair Salon (BUT-0001) is the pilot. Any other high-street type follows the identical loop.
