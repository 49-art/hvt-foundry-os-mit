## Items Flagged, Not Corrected

Per standing practice, discrepancies in a supplied document are noted, not silently edited into the source:

1. Missing dependency. DOC-0005’s own front matter lists dependencies as HVT-0001 Art. VIII, Art. XIV, DR-2026-08-04-06, and ENG-0004 — but the document body explicitly instructs using “the existing Business Ontology (HVT-0006)” in Step 2, and names WKF-0001 as the workflow it operationalizes and BUT-0001 as its pilot target. None of HVT-0006, WKF-0001, or BUT-0001 appear in the stated Dependencies line. The registry entry (§ below) and the graph relationships record the fuller, accurate dependency set; the document file itself is left as supplied.
2. “The customer is always right” / “the customer’s stated reality overrides any prior classification.” As flagged in DR-2026-08-04-06’s Filing Note, this principle is not yet codified anywhere in HVT-0001. DOC-0005 now states it twice more, as an operative instruction (“Let the owner correct anything”) rather than aspiration. This raises the same open question as before, now with more weight behind it: if a procedural document is actively instructing Foundry agents to let a customer override a formal classification, that instruction should probably rest on a Constitutional clause, not on accumulated practice across three documents that each assume it without stating it as law. Still not resolved here — flagged again, now with a recommendation attached: the next Constitutional amendment pass should consider a clause under Article XIV or as new Article XIV.6, something to the effect of “a customer’s stated correction to their own classification takes precedence over the Foundry’s prior classification, pending review” — bounded (“pending review”) so it doesn’t read as unlimited authority to override the Configurator’s output without any Foundry check at all.

## Rationale

Registering DOC-0005 in HVT-0003 rather than leaving it as a standalone file keeps it inside the same traceable asset ledger as every other Documentation asset (DOC-0001, DOC-0004), queryable and versioned the same way. The flagged items are logged rather than fixed because DOC-0005 is Howard’s authored procedure — correcting its wording without consultation would violate the same standing instruction this whole session has followed.
